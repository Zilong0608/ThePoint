# 上线准备：按这个顺序处理

当前：本地功能和数据库已接好；公网部署、发信、域名、HTTPS、异机备份及真实环境验收尚未完成。

## 1. 改正式管理员密码

- [ ] 登录后台，使用“修改我的后台密码”设置自己的密码。
- [ ] 核对员工列表，按需要分配编辑、审核、客服权限。

已有数据库的密码不会因填写 `ADMIN_INITIAL_PASSWORD` 自动改变。该变量只用于首次创建新库。

## 2. 确定域名

- [ ] 查询并购买准备长期使用的域名，账号由自己持有。
- [ ] 确认续费费用，开启到期提醒。

购买路径见 [上线配置说明](上线配置说明.md)。买域名不等于买网站服务器，也不自动创建收件邮箱。

## 3. 确定正式服务器与持久存储

- [ ] 选择可运行 Node.js 的服务器或平台，确定部署地区。
- [ ] 配置数据库、上传图片和备份目录的持久存储。
- [ ] 迁移 `storage/data.sqlite` 与 `storage/uploads/`，确认三套房源及地图坐标保留。
- [ ] 配置进程自动启动、异常重启和服务日志。

目前继续使用 SQLite 即可，不要求另外购买 Supabase。当前是单实例方案；需要多实例时，再安排数据库与文件存储迁移。

## 4. 绑定域名与 HTTPS

- [ ] 域名解析到正式服务。
- [ ] 平台托管 HTTPS，或配置 Caddy 等反向代理。
- [ ] 设置正式 `PUBLIC_SITE_URL`，并检查后台站点 URL。
- [ ] 设置安全 Cookie；只有经过可信代理时才开启代理配置。

## 5. 接通系统邮件

- [ ] 注册 Resend，或使用现有企业邮箱的 SMTP。
- [ ] 验证发信域名，填写服务商要求的 DNS 记录。
- [ ] 填写 SMTP 和 From，发送后台测试邮件。
- [ ] 在正式域名实际走一遍“忘记密码”，核对收件、链接地址和新密码登录。

API Key 与密码只填在后台或服务器配置中，不要发到公开仓库。系统发信服务与人工接收客户邮件的邮箱分别安排。

## 6. 设置异机备份与报警

- [ ] 每天将完整备份自动传到独立设备或存储。
- [ ] 设置保留周期和失败提醒，限制备份访问权限。
- [ ] 下载一份备份，实际执行校验及空目录恢复演练。
- [ ] 给 `/healthz` 配置外部可用性监控，并确认报警能收到。

当前自动备份只写本机。不能因为开启了本机备份就跳过异机保存。

## 7. 核对正式内容并验收

- [ ] 核对房源地址、坐标、价格、图片、状态及负责人。
- [ ] 补齐原有资讯中待编辑的正文，确认图片和内容可公开使用。
- [ ] 核对联系方式、合作伙伴及服务介绍；演示账号、商家与帖子已经清除。
- [ ] 手机和电脑分别验证注册、登录、收藏、地图搜索、咨询与预约。
- [ ] 验证后台发布、审核、图片上传、权限、退出及重启后数据仍然存在。

费用开通、域名购买和外部账号授权需要由你决定；代码整理没有执行这些外部操作。
