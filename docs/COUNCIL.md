# Auckland property research

Entry: `/council.html`, linked from shared desktop/mobile navigation and footer. This is independent of the uploaded property listing map. No sample council records are inserted into the database.

Address search automatically selects a single untruncated match, centres the map, opens a labelled marker and scrolls to the results. Multiple address matches require selection. The public page requests automatic primary-parcel selection: exactly one untruncated, non-road/water parcel with valid geometry and purpose can be used automatically. Ambiguous results stay as point queries and require selection. This never equates a primary parcel to an apartment title or the whole property. Layer badges distinguish returned features, no intersecting records and source failures.

## Data sources

- LINZ addresses: https://data.linz.govt.nz/layer/123113-nz-addresses/ links to official item `3632c8130f034ff8bbfb122a50533550`. The obsolete 105689 layer must not be used. Query the LINZ-owned `LINZ_NZ_Addresses/FeatureServer/0`, restrict to Auckland and Current addresses. Require a street number to avoid unbounded national text searches. API returns up to 20 candidates; user selects the address, including the correct apartment number.
- LINZ primary parcels: https://data.linz.govt.nz/layer/50772-nz-primary-parcels/ links to official item `7442ad2e98534d67a3c45df9b7fbcf5e`, `LINZ_NZ_Primary_Parcels/FeatureServer/0`. CC BY 4.0, commercial reuse with attribution. Primary parcels may include roads/water; they are not a legal property report or apartment title boundary.
- Auckland Council Base Zone: official organisation `n4yPwebTjJCmXB6W`, item `232d7b39839d4616bcbfc0509e26d9b3`, `Unitary_Plan_Base_Zone/FeatureServer/0`. Decode numeric domains using that layer's own metadata. Do not declare every record operative. The old `arcgis3/.../UnitaryPlanZones` service is labelled Working Version and is not the source used for zoning here.
- PC120 public summary: official Council item `272856763af84fd09d5cb07b971cda7d`, `RPC_PROD_Plan_Change_Property_Summary/FeatureServer/0`. The source explicitly identifies this as the public display layer. The UI must identify PC120 coverage, not imply it includes all plan changes or that proposals are operative. Source metadata and Council use terms remain linked for verification.
- General plan changes: Council `arcgis/rest/services/UnitaryPlan/UnitaryPlanAppealsandModifications/MapServer/5` is now connected separately from PC120 summaries. It returned the PC120 partial withdrawal/proposed-amendment notice dated 27 August 2026 during live verification. The earlier `arcgis3/NonCouncil` endpoint is not used. The general spatial layer is not guaranteed to cover every unmapped or private change; the official register remains linked.

Only public official endpoints are queried. No API key or Supabase migration is required. Upstream concurrency is limited to four fetches, with a bounded queue. Successful queries cache for one minute, incomplete queries five seconds and metadata one hour; cache limits are 200 entries, 24 MiB of serialized payloads total and 8 MiB per entry. Requests for the same key share one in-flight operation. These limits bound serialized cache size, not exact V8 heap consumption. Public endpoints allow 20 requests per IP per minute. No bulk harvesting or automatic map-panning queries. Review Council's current use terms before large-scale reuse: https://www.aucklandcouncil.govt.nz/geospatial/how-to-use-council-open-data/Pages/user-licence-auckland-council-open-data.aspx . Source notices require independent verification and do not grant an accuracy warranty.

## Accuracy and failure behaviour

Manual parcel selections are re-read from LINZ and constrained to intersect the query point. Automatic selection follows the uniqueness/purpose rule above. Arbitrary public client-supplied query geometry is never accepted. GeoJSON rings are converted to Esri clockwise exterior/counterclockwise holes without losing multipart geometry. Intersections can include boundary touches and do not establish coverage ratios. Unsimplified polygon records are marked for whether they contain the address point; other zoning/PC120 records are collapsed separately with an explicit neighbour/boundary warning and original summary addresses. Equal general-plan-change notices are grouped in the text while retaining all returned geometry and source-record downloads.

Each source has independent `ok` / `unavailable` results. Unknown source update dates stay unknown, never replaced with the retrieval date. Invalid coordinates and nonnumeric parcel IDs are rejected. No selected-parcel fallback to approximate point data. Source strings are escaped before display; only official HTTPS links are rendered as links. English and Chinese UI use the existing site language selector; original authoritative field values are preserved.

Public presentation starts with an overview, translated zoning and source record status. Internal object/global IDs and validation fields are not shown. Chinese zone/status names and two verified PC120 source explanations use explicit mappings. Unknown paragraphs show a translation-pending notice; English mode does not fall back to Chinese prose. Addresses, title IDs and brand names remain original identifiers. Record downloads preserve original numeric attributes; query results also include decoded labels for display. Source dates are collapsed by default and attribution remains visible.

## Master plans / structure plans

Administrator-only **Council 规划文件** supports adding, editing, hiding and deleting documents, original dates, optimistic edit-version checks, and optional imported WGS84 Polygon/MultiPolygon coverage. Polygon validation bounds size/coordinates, closure and nonzero ring area; it does not replace staff review of topology or legal applicability. Rectangle bounds are computed from imported geometry. The API matches polygons to the chosen parcel (or point fallback), with holes/multipart support; rectangle-only records remain explicitly editorial coverage. Expensive/invalid stored geometry is surfaced as an uncertain overlap, never silently declared absent. Only published rows enter public lookup/search APIs. The document library is a catalogue search, not a property match.

`council_documents` is created idempotently on startup and lives in the existing SQLite database, included in standard backups. Source lookup results are not stored as authoritative property records. Secrets remain outside frontend files.

## Verification and launch

Run `npm run check`, `npm test`, and `npm run test:browser`. Unit tests use injected responses and in-memory SQLite; browser fixtures exist only within the test, not public assets. Real source connectivity must be checked separately; mocked tests do not prove official service uptime.

Before promising the client full coverage: verify address/parcel matching for unit titles, rural lots and multiple parcels; confirm current planning statuses against the plan text; collect and review actual master/structure plan documents; monitor official service uptime and usage terms. This implementation is Auckland-first, not a nationwide Relab replacement, and does not include LIM reports, owners' personal information, valuations, title certificates or automatic development feasibility conclusions.

Live verification on 2026-10-19 initially showed parcel spatial/output queries timing out at 12 seconds; a later query returned a real parcel after approximately 15 seconds. Parcel lookup now queries intersecting object IDs first, validates/bounds the ID list, then fetches those geometries by object IDs without repeating the spatial filter. The ID query is constrained by the chosen parcel ID when one is supplied, preventing unrelated parcel selection. Real address-point and whole-parcel requests succeeded for `104/22 Library Lane` (parcel 7770098, `Lot 1 DP 506481`, survey area 3856 m²) and `232 Lonely Track Road` (parcel 5016694, `Lot 2 DP 203295`, survey area 10014 m²). These are observed source records, not title-area or development conclusions. Availability remains dependent on the upstream service.

## Additional related planning layers and reference library

Council `Precincts/FeatureServer/0` (item `af4498ca745f475cbfe6a361b4f10663`) and `Designation/FeatureServer/0` (item `2a8b054667614bfdb31a83167be812d4`) are queried by point or selected parcel polygon alongside zoning and PC120. Both originate from Council's `OpenDataUser` account, with public/business reuse terms linked in their official metadata. Each result has separate status, source metadata and a map toggle. No intersection is not a guarantee of no planning restrictions; these layers are not a complete plan-change register. Chinese explanatory labels do not invent translations of unknown place-specific record names; original records remain downloadable.

`src/domain/council-references.js` contains verified official regional PDF links and printed document dates: the Dairy Flat/Silverdale spatial strategy (14 March 2024) and Silverdale West/Dairy Flat industrial structure plan (April 2020, published as PC103 Appendix 4). The UI places these in a distinct regional-reference card. They are never inserted as property-applicable matches or assigned guessed spatial extents, adoption status, or current legal effect. Staff-curated property-coverage documents remain separate in SQLite.

## Extended official layers, map and reports

Council open-data services additionally supply `Flood_Plains`, `Flood_Prone_Areas`, `Overland_Flow_Paths`, `Stormwater_Pipe`, and `Height_Variation_Control` (layer 0). General Council services provide `LiveMaps/Planning/MapServer/3` (Plans and Places), and `LiveMaps/UndergroundServices/MapServer/52` and `/5` (local water/wastewater pipes). These are distinct from complete transmission networks, building/resource consent histories, LIMs, insurance assessments or development feasibility. Whitelisted fields avoid downloading unrelated staff/creator attributes.

Some general change and flood geometries exceeded the 4 MB source-response guard. For general changes, planning areas and flood plains only, the service requests simplified output geometry (`maxAllowableOffset=0.00001`, `geometryPrecision=6`). The parcel and spatial query inputs stay unsimplified. The UI and downloads identify simplified display shapes, which must not be used for measurement. Address-point membership is not inferred from those simplified shapes.

Each layer has an independent toggle, colour, source and error state. Map popups link to the corresponding result record. Reports offer range location, full-query JSON, record JSON, printable/savable PDF through the browser, and a copyable query link. Shared links carry coordinates, optional parcel, address label and language; recipients explicitly query for fresh data. Print events expand source/record details then restore their prior state. Library content is excluded from the property printout.

Live checks covered 232 Lonely Track Road, 104/22 Library Lane and 65 Lascelles Drive. The latter returned positive flood-prone/flow-path records and an official planning-area record for Silverdale West Dairy Flat. Its GIS project stage is historical (`draft in progress`), so the UI does not treat it as the latest approval status. A reviewed exact-title join offers the verified 2020 reference PDF without asserting current legal applicability. Real source checks are observations, not an uptime guarantee.
